**Stage-1 Differences (Ours vs. Original)**
- **Data construction:** Our collate builds a `<background>` prompt with repeated `<mem_i>` placeholders and supports variable doc counts, padding memory embeddings when needed [src/lamb/clara_collate.py#L116-L282](src/lamb/clara_collate.py#L116-L282). The original pipeline fixes `generation_top_k` docs per sample and formats prompts via chat roles (`_blend_prompt_and_memory_tokens`) before tokenization [_.extra/ml-clara/openrlhf/datasets/sft_dataset.py#L112-L204](.extra/ml-clara/openrlhf/datasets/sft_dataset.py#L112-L204) and [_.extra/ml-clara/openrlhf/models/modeling_clara.py#L975-L1058](.extra/ml-clara/openrlhf/models/modeling_clara.py#L975-L1058).
- **Model encoding/embedding replacement:** Our encoder runs once to produce hidden states, which are compressed by `DocumentCompressor` and later injected into decoder embeddings with a simple positional walk [src/lamb/clara_model.py#L204-L318](src/lamb/clara_model.py#L204-L318). The original model appends memory tokens directly to encoder inputs, relies on tokenizer-provided `mem_tokens`/`sep_token`, and replaces decoder slots using a fixed slot length derived from `generation_top_k` and `compr_rate` [_.extra/ml-clara/openrlhf/models/modeling_clara.py#L857-L999](.extra/ml-clara/openrlhf/models/modeling_clara.py#L857-L999).
- **Loss composition:** Our training loop separates QA vs. paraphrase samples, scales them independently, and optionally adds an MSE term from the compressor [src/lamb/clara_train.py#L180-L281](src/lamb/clara_train.py#L180-L281). The original stage-1 forward path treats the batch as a single LM loss (chat prompt masking handles task differences) and only augments with the compressor-side MSE returned by `compress` [_.extra/ml-clara/openrlhf/models/modeling_clara.py#L1545-L1586](.extra/ml-clara/openrlhf/models/modeling_clara.py#L1545-L1586).
- **Prompt templates:** We now expose both styles—our simpler `<background>` template and the original system/user chat prompts (QA paraphrase instructions) via `build_original_*` helpers and a dedicated collate branch [src/lamb/clara_collate.py#L145-L408](src/lamb/clara_collate.py#L145-L408). The original prompts come verbatim from the reference implementation [_.extra/ml-clara/openrlhf/models/modeling_clara.py#L975-L1058](.extra/ml-clara/openrlhf/models/modeling_clara.py#L975-L1058).
- **Doc count handling:** Our pipeline pads memory embeddings to the longest sample so mixed doc counts are allowed [src/lamb/clara_train.py#L206-L245](src/lamb/clara_train.py#L206-L245). The original flow assumes uniform doc counts and reshapes embeddings accordingly; `--use-clara-original` now enforces this shape to mirror the reference behavior [src/lamb/clara_train.py#L206-L245](src/lamb/clara_train.py#L206-L245).

**New toggle**
- Pass `--use_clara_original True` (or set `ClaraConfig.use_clara_original=True`) to enable the original-style stage-1 data formatting, prompt templates, and loss mixing.
